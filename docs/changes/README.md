## 📋 文档命名规范

### 目录命名格式
```
YYYY-MM-DD_description/
```

- **YYYY-MM-DD**: 变更发生的日期（ISO 8601 格式）
- **description**: 变更内容的简短描述（使用小写字母和连字符）

### 文件命名格式
```
CHANGE_REPORT.md
```

每个变更目录下固定使用 `CHANGE_REPORT.md` 作为变更报告文件名。

## 修改文件清单

## 测试验证

[测试场景、测试结果、验证清单]

## 🗂️ 变更分类

### 按变更类型分类

1. **功能新增 (Feature)**
   - 新增功能模块
   - 新增 API 接口
   - 新增用户界面

2. **功能修复 (Fix)**
   - Bug 修复
   - 交互问题修复
   - 显示问题修复

3. **性能优化 (Performance)**
   - 响应时间优化
   - 内存使用优化
   - 数据库查询优化

4. **重构 (Refactor)**
   - 代码重构
   - 架构调整
   - 模块拆分/合并

5. **文档更新 (Documentation)**
   - 用户文档更新
   - 技术文档更新
   - API 文档更新

### 按影响范围分类

1. **核心功能变更**
   - 影响核心业务流程
   - 需要回滚预案

2. **一般功能变更**
   - 影响局部功能
   - 常规测试验证

3. **辅助功能变更**
   - 影响辅助功能
   - 简单验证即可

## 📊 变更管理流程

### 1. 变更申请
- 填写变更申请单
- 明确变更内容和影响范围
- 指定变更负责人

### 2. 变更评审
- 技术负责人评审
- 评估变更风险
- 确定变更时间窗口

### 3. 变更实施
- 创建变更分支
- 实施变更内容
- 编写变更报告

### 4. 变更验证
- 功能测试验证
- 性能测试验证
- 回归测试验证

### 5. 变更归档
- 整理变更文档
- 归档到对应目录
- 更新索引文件
